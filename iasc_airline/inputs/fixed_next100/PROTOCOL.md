# Fixed additional native-record coverage: ranks 101–200

This follow-up protocol is fixed before comparative execution but after results
from the first 100-account study were known. It is a separate development-led
extension of that study, not a retrospective preregistration, unseen benchmark
test, independent dataset, or confirmation that generalizes beyond the database.

## Question and fixed inputs

Does the unchanged qualification-to-permission connection retain its observed
dispatch behavior on the next 100 different accounts and reservations from the
original fixed structural sequence? Preserve eligible-action completions and
separately count dispatch on ineligible, missing-information and transfer cases.

Use original `COHORT_SELECTION.json` from
`ecrc_native_record_coverage_2026-09-15`, with seed
`ecrc-native-record-coverage-v1`. Take its original 418-account sorted pool at
global ranks 101 through 200 inclusive. Use each row's already determined first
owned reservation under the original reservation hash. Do not examine business
qualification when choosing records; no replacements or positive oversampling.
Selection uses archived IDs, structural links and hash ranks, not native status,
insurance, cabin, creation time, reason outcomes or benchmark gold.

The original exclusion snapshot defines the original pool. A separate snapshot
of current saved runtime call arguments documents any additional known exposure
without changing this fixed sequence. Prior global database access cannot be
excluded. Do not call these never-seen records or an independent holdout.

Run health, other and unspecified reason templates once each per reservation,
unchanged from the first batch: 100 accounts, 100 reservations, 300 contexts.
Scripted confirmations and explicitly supplied reservation IDs remain shared.
100 is a fixed local resource budget, not a power calculation or positive-case
target. The number of eligible requests is an outcome, not a stopping rule.

## Fixed actors and controlled execution

Use all four unchanged conditions in the original rotating order:
direct_native_dispatch, qualification_ecrc, existing_rules_only, and
without_claim_evidence_requirement. There are exactly 1,200 primary cells.
The direct workflow has common factual queries, ownership resolution and action
confirmation but does not compute business qualification. The business-rules
workflow uses the domain rules directly. ECRC requires positive qualification
evidence at its permission boundary. Claim ablation retains the checker and only
removes that required positive evidence dependency. Preserve all existing shared
capabilities. Keep ECRC/business-rule ties and successful direct executions.

The thin new runner imports the previous coverage runner without editing it,
redirecting its study root and extending source hashes. It reuses the previous
`one`, native replay and full-grid batch code. Each cell uses a fresh unmodified
native environment from pinned tau2-bench commit
`2174a603f6d014ef94473ffa95957f6ce27100db`; each gate gets a separate database.
Keep the common original native policy clock, K=100 nonbinding count limit,
128-call per-cell technical cap, selector, checker, policies and evaluator.
There is no model, human participant, live service, API expense, metadata fault,
budget contention, native atomic completion receipt or recovery experiment.

## Recorded evidence and evaluation

Retain the frozen request denominator, all four arms and every outcome. Store
shared immutable full BEFORE_DB plus cell references; complete gzip AFTER_DB,
native calls/responses, confirmations, actor output, independent case evaluation,
permission database/state, and fresh-environment replay of every recorded call.
Replay checks all responses and complete final state; it is validation work,
not additional independent data. An independent auditor reconstructs effects,
scope, eligibility, confirmations and permission state from raw evidence rather
than relying on the actor's result labels.

Report per arm and reason: eligible/eligible completed/eligible missed,
known-ineligible executions, missing-information executions, transfer-required
executions, unresolved selections, out-of-selection/duplicate effects, native
calls/writes, errors and technical failures. Missing reasons and required human
transfer remain unfinished; withholding dispatch does not complete those tasks.
Positive outcomes here mean native policy-qualified cancellation, not customer
benefit, money saved, true sickness, or full benchmark conversation success.

Count 300 paired contexts on 100 distinct records, not 300 independent customers
or 1,200 independent tasks. Report this extension separately from the first
batch; any combined descriptive totals must show both denominators and that this
new plan followed knowledge of the first batch. Do not infer population zero
error rates or attach iid binomial intervals to the repeated fixed templates.

## Freeze, failures and stopping

Before comparisons freeze source selection, all requests, this protocol, wrapper,
unchanged implementation/evaluator files, native vendor, audit tools and current
manuscript. Synthetic QA may validate existing mechanics; it is not a native
comparative result. The complete 1,200-cell grid runs once. Stop after the fixed
grid regardless of eligible count, direction, ties or absent ablation benefit.
Retain incomplete and technically failed cells. A discovered implementation or
runner error requires documented repair, versioned freeze and retention of all
originals, followed by all affected conditions, not favorable-cell replacement.

Boundary fixtures belong to a separate study and are never added to this
unmodified-record denominator. This execution task does not update the paper,
Overleaf or GitHub. Review the complete audited results before deciding what
evidence merits a manuscript revision.
